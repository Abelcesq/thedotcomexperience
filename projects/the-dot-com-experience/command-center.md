# Command Center — The Day-to-Day Operating System (Step 4)

> Purpose: identify the continuous tasks that must get done, how they feed each other, how
> they communicate, and how goals break down across time so we can spot bottlenecks. This is
> the design; the live tracking lives in `dashboard.md` (and a tool, once chosen in Phase 3).

---

## 1. The task taxonomy (the recurring "engines")
Every activity belongs to one of five engines. Each engine produces an output that **feeds**
the next, so nothing happens in isolation.

| # | Engine | Continuous tasks | Produces | Feeds → |
| - | --- | --- | --- | --- |
| 1 | **Discover (Insight)** | study, reflect, capture ideas, talk to people | raw philosophy + audience insight | Content, Product |
| 2 | **Create (Content)** | draft posts/scripts in-voice, design visuals | on-brand content | Distribute, Brand |
| 3 | **Distribute (Audience)** | publish, engage, grow list | reach + email list | Relationship, Offer |
| 4 | **Offer (Monetize)** | define offers, merch, sales | revenue + validated demand | Steward, Discover |
| 5 | **Steward (Govern)** | audits, board consults, finances, ethics | decisions + course-corrections | all engines |

**Data flow (how tasks communicate):**
`Discover → Create → Distribute → Offer → Steward → (back to) Discover.`
Insight becomes content, content earns audience, audience enables offers, offers fund
stewardship, stewardship redirects discovery. A blockage in any engine starves the next —
that's where to look when results stall.

## 2. The communication contract (so nothing is missed)
The **file system is the single source of truth.** Every engine reads/writes Markdown so no
data is lost in someone's head or a chat thread.
- **Insight** → captured in `knowledge/` (brand, purpose) and an idea log.
- **Decisions** → recorded via the `board-of-directors` skill output, stored in the project.
- **Status** → `dashboard.md`, refreshed by `continuously-improve`.
- **Daily intent & review** → the daily log (template below).
- **Rule:** if it isn't written down in the container, it doesn't exist. This is the
  movement's own "integrity of the word" principle applied to operations.

## 3. Goals broken down across time (year → second)
The point of breaking goals down is to **place every task on a timeline** and expose
efficiency/bottlenecks. Granularity by horizon:

| Horizon | What it holds | Review |
| --- | --- | --- |
| **Year** | the North-Star direction + the 1 primary 12-month "win" (`clarity.md` Q3) | quarterly |
| **Quarter (90 days)** | the current Phase's exit test (`roadmap.md`) | monthly |
| **Month** | 1–3 outcomes that move the phase forward | weekly (light audit) |
| **Week** | the 3–5 tasks that produce those outcomes; content cadence | daily |
| **Day** | top 1–3 "promises to self" + the recurring engine tasks | end of day |
| **Hour / minute / second** | focus blocks; the unit where discipline is actually kept | in the moment |

> Note on hours/minutes/seconds: don't *schedule* the seconds — **protect** them. At that
> resolution the lever is attention and integrity (Jim Rohn: *"what's easy to do is easy not
> to do"*). The system's job is to make the day's 1–3 promises unambiguous so the small units
> take care of themselves.

## 4. Daily operating rhythm (template)
```
DATE:
Direction check — does today serve the current phase's exit test? (y/n + why)
Top 3 promises to self (today's non-negotiables):
  1.
  2.
  3.
Engine tasks touched today: [Discover] [Create] [Distribute] [Offer] [Steward]
Bottleneck noticed:
End-of-day review — promises kept? (this builds self-esteem / "magic dust")
Carry-forward:
```

## 5. Bottleneck detection (the weekly question)
Each week ask, per engine: *what is the constraint?* Apply Munger's inversion — *"what would
guarantee this engine fails?"* — and fix the binding constraint first. Most early-stage
movements bottleneck at **Distribute** (no audience) long before **Offer** (no product), which
is exactly why the roadmap front-loads content and list-building.

## 6. From design → live system
- **Now:** track via `dashboard.md` + the daily template above (zero cost, works today).
- **Phase 3:** choose a tool to host this (options to weigh with the board: a Notion/Obsidian
  workspace, a simple task app, or a lightweight custom dashboard fed by the repo). Decision
  deferred until there's enough activity to justify it — don't build the cockpit before the plane.
